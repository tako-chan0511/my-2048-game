# 2048カスタム

Vue 3 + TypeScript strict + Viteで動く、独立した2048ゲームです。バックエンド・APIキー・環境変数は不要です。

## 起動

Node.js **22.23.4**（`.nvmrc`）、npm **10.9.9**を基準にしています。

```bash
cd ~/projects/my-2048-game
nvm install
nvm use
# npmのバージョンが異なる場合に実行
npm install --global npm@10.9.9
npm ci
npm run dev
```

ターミナルに表示されたローカルURLを開いてください。`npm ci`でlockfileに固定した依存関係を再現できます。

## 遊び方

- 初期設定は4×4・目標2048・初期2枚・4が10%です。盤面3×3〜10×10、目標128〜65536、初期1〜全マス、4の確率0〜100%へ変更できます。
- 矢印キー、盤面のスワイプ、画面の上下左右ボタンで全タイルをスライドします。
- キーボードは盤面またはゲーム内のボタンにフォーカスがある間に操作できます。Tabキーで移動できます。盤面をクリック／タップしてもフォーカスできます。
- 矢印キーの長押しは繰り返し移動させません。1回の押下で1手です。設定入力欄やゲーム領域外のキー操作は妨げません。
- スワイプは24 CSS px以上、主方向が明確な場合に指を離すと1手です。複数指・キャンセル・曖昧な斜め操作は移動しません。盤面外では通常通りページをスクロールできます。
- 同じ数字が隣り合うと合体し、合体後の数字をスコアに加算します。
- 一度の移動で同じタイルを二度合体させません。例：`2,2,2,2 → 4,4,0,0`（加点8）。
- 盤面が変化した場合だけ手数を1増やし、新規タイルを1枚出現させます。既定は2が90%、4が10%で、初期配置にも適用済みの確率を使用します。
- 変化しない操作では、盤面・スコア・手数・乱数状態・タイルIDを変更しません。
- 適用した目標数字への到達時は「○○達成！おめでとう！」とスコア・手数・最大数字を表示します。「続ける」で再開でき、同じゲームでは再表示しません。
- どの方向にも動かせなくなるとゲームオーバーの結果を表示します。「盤面を見る」で閉じても終了状態は維持します。
- ポップアップ中はゲーム操作と背景スクロールを止め、フォーカスを内部に移動します。Tab／Shift+Tabはポップアップ内を循環します。Escキーは「続ける」／「盤面を見る」と同じ動作です。
- 目標達成とゲームオーバーが同時の場合は、お祝いを閉じてからゲームオーバーを表示します。
- 「新しいゲーム」は現在適用中の設定を使って盤面・スコア・手数・達成状態をリセットします。
- 「次のゲームの設定」を編集してもプレイ中のゲームは変わりません。「この設定で新しいゲーム」を押したときだけ適用します。不正な設定や開始失敗時は現在のゲームを維持します。
- 設定値を自動補正しません。盤面を小さくして初期枚数が多すぎる場合は、枚数を手動で直してください。
- 全マス配置は開始直後に手詰まりになる場合があります。その場合は0手でゲームオーバーを表示します。
- 証明できる到達不能条件には事前警告を表示します。目標を勝手に変えず、その設定でスコアを目指して開始することもできます。上限以下の目標の達成を保証する表示はしません。
- 大きな盤面では必要に応じて`2^16`等の指数表記を使います。「タイルの正確な数字を確認」を開くと、位置と省略しない値をキーボード・タッチの双方で確認できます。

Undoの初期上限は**10回**です。設定は0〜10回・無制限に対応します。通常・時間制限・手数制限の3モードに対応しています。タイルの移動・合体・出現アニメーションに対応しています。

## タイルの演出

- 移動元・移動先を145msでスライドし、その後120msで合体したタイルと新規タイルを拡大表示します。
- 高速入力は待ち行列に入れず、前の演出を破棄して最新の移動へ切り替えます。スコア・手数・乱数・保存は入力時に確定し、演出完了では変更しません。
- Undo・新しいゲーム・画面サイズ変更・ポップアップ表示時は演出を破棄し、確定済み盤面を表示します。復元時も途中の演出は再生しません。
- OS／ブラウザの「動きを減らす」設定に対応し、`prefers-reduced-motion: reduce`では移動・拡大演出を省略します。

構造と制御の詳細は[アニメーション仕様](docs/animations.md)を参照してください。

## ゲームモード

- 通常：時間・手数の制限なし。目標達成後も続けられ、手詰まりだけで終了します。
- 時間制限：10〜3600秒の整数、初期値300秒。最初の有効な移動で開始し、無効移動では開始しません。残り時間を分・秒で表示します。
- 時間制限はポップアップ中・タブ非表示中・ページを閉じた間も進みます。締切以降の移動とUndoは受け付けません。
- 手数制限：1〜100000手の整数、初期値1000手。盤面が変化した移動だけを数え、最後の合体・スコア・新規タイルを確定してから終了します。
- 手数上限や手詰まりは、履歴とUndo回数があれば戻って再開できます。時間切れからはUndoできません。
- 目標達成と終了条件が重なった場合は達成を先に表示し、「結果を見る」で終了結果を表示します。達成通知を閉じても締切は延長しません。
- モードや制限値の編集は現在のゲームへ適用せず、「この設定で新しいゲーム」を押した場合だけ適用します。

詳細な時刻・終了理由・保存互換性は[モード仕様](docs/modes.md)を参照してください。

## Undoと記録・自動保存

- 「Undo（1手戻す）」で盤面・スコア・手数・乱数・次のタイルIDを戻します。Undoして同じ方向へ動かすと、同じ新規タイルが出現します。
- 無効な移動は履歴へ入れません。Undo使用数と過去の目標達成・通知は戻りません。新しいゲームでは履歴と使用数を初期化します。
- 達成後は「続ける」で閉じてからUndoできます。手詰まり後は「Undoで続ける」、または「盤面を見る」で閉じてUndoできます。履歴・回数がなければボタンは無効です。
- 「同条件のベストスコア」はサイズ・目標・初期枚数・出現確率・Undo上限・モードとその制限値ごとに管理し、シードは区別しません。有効な移動ごとに更新し、Undoや新しいゲームで下げません。
- 進行とベスト記録を別々のlocalStorageキーへ保存します。進行には適用済み設定、盤面、スコア、手数、乱数、履歴、Undo使用数、達成・通知状態、時間制限の開始・締切・最後に観測した時刻を含めます。編集途中の設定は保存せず、再読み込み時は適用済み設定を表示します。
- スコアは10進文字列で保存し、復元時に型・バージョン・範囲・盤面や履歴の整合性を検証します。不正な進行データは復元せず、新しいゲームを開始します。有効なベスト記録は保持します。
- 保存が拒否された場合もゲームとUndoはこの画面で継続でき、保存できなかったことを表示します。
- 無制限Undoの履歴はメモリ上では自動削除しません。保存容量・処理量の上限を超える場合は現在の盤面を優先し、履歴を保存できなかったことを表示します。この場合、再読み込み後は以前の履歴を使えません。

保存形式と上限、終了理由に対するUndoの扱いは[保存・Undo仕様](docs/persistence.md)を参照してください。

## 検証

```bash
npm run test
npm run typecheck
npm run lint
npm run build
npm run preview
```

Vitestは固定シード・独立した参照アルゴリズムで合体・全方向移動・乱数消費・盤面合計を検証します。Vue Test Utilsで状態管理、3種類の入力操作、結果ポップアップとフォーカス制御も検証します。GitHub Actions用のCI設定は、クリーンインストール→型チェック→ESLint→テスト→ビルドを実行します。公開前にローカルでも同じチェックを実行してください。

## 構成

```text
src/
  core/             # N×Nエンジン・設定検証・Undoセッション。Vue非依存
  composables/      # 共通操作・保存の接続・キー・Pointer Events
  components/       # 盤面・次のゲーム設定・結果ポップアップ
  presentation/     # エンジンの移動結果を表示用座標・演出へ変換（保存しない）
  input/swipe.ts    # Vue非依存のスワイプしきい値・方向判定
  services/         # バージョン付き保存形式・localStorage・容量不足対応
  App.vue           # 入力・フォーカス・結果表示の接続
  style.css         # 白いカード型、320px幅対応
  main.ts
tests/              # エンジン・状態管理・画面テスト
docs/engine.md      # 型、移動、乱数と将来の復元の契約
docs/settings.md    # 適用ルール・到達不能の数学的判定
docs/persistence.md # Undo・記録・保存形式・容量不足の扱い
docs/modes.md       # 時間・手数制限、時刻注入、終了の優先順位
docs/animations.md  # 表示層のスライド・合体・出現、破棄と動き軽減
docs/step6-report.md # STEP 6の変更一覧・最終品質確認結果
.github/workflows/ci.yml
```

スコアとタイルの数値計算には`bigint`を使用し、タイル自体は指数`power`で保持します。詳細は[エンジン設計](docs/engine.md)を参照してください。

## 依存関係

依存は独立した`package-lock.json`に固定し、他プロジェクトの`node_modules`は参照しません。開発ツールが使用する`glob`と`minimatch`は、npm auditで検出した問題の修正版へ`overrides`で固定しています。更新時は`npm ci`と全チェックを再実行してください。
