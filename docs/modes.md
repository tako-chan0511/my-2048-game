# STEP 5 モードと時計

## 設定と適用

通常、時間制限（10〜3600秒、初期300秒）、手数制限（1〜100000手、初期1000手）を選択できます。すべて整数で検証し、空欄・小数・NaN・Infinity・未知モード・不明な項目を拒否します。編集中は現在のゲームを変更せず、有効な設定で「この設定で新しいゲーム」を実行した場合だけ適用します。

通常モードは時間・手数制限がなく、従来の盤面・合体・乱数・Undoを使います。追加モードの判定はPlaySession層が担当し、スライド・合体・新規タイル生成を担当するゲームエンジンは変更しません。

## 時間制限

最初の有効な移動を受け付けた時刻をstartedAtMs、そこに制限秒数×1000を加えた値をdeadlineMsとして保存します。初期配置・開始前の無効移動・編集操作では開始しません。

```
observedNow = max(入力された現在時刻, lastObservedAtMs)
remainingMs = max(0, deadlineMs − observedNow)
時間切れ = observedNow >= deadlineMs
```

締切ちょうども移動不可です。各移動・Undo・結果の閉じる操作が現在時刻を確認するため、表示更新が遅れても締切後の操作を受け付けません。有効な移動が締切前に受け付けられた場合は、その移動を確定します。新しいゲームは時計を未開始へ戻します。Undoでは開始・締切を戻さず、全移動をUndoして手数0になっても同じ締切を使用します。

時計はDate.nowを使う関数をcomposableへ注入します。純粋なコアはDate、performance、setIntervalを使用しません。テストでは数値の時刻を直接渡します。

表示用intervalは1コンポーネントに最大1本、250ms間隔です。残秒を減算せず、毎回締切との差を計算します。ポップアップ・手詰まり表示中も時間制限は進みます。時間切れ・新規開始・通常／手数モードへの切替・アンマウント時にintervalを解除します。

非表示化・pagehideで時刻を再確認して保存し、表示に戻ったときも再確認します。ページを閉じた間にintervalが動かなくても、再読み込み時の現在時刻と保存済み締切で経過を反映します。残量は切り上げた分・秒（例：05:00、00:01）で表示し、開始後30秒以下は色と「残りわずか」の両方で警告します。

現在時刻の逆行で残量を増やさないよう、最後に観測した時刻を保持します。ただしバックエンドを使わないため、端末時計の正しさを認証する機能ではありません。保存できない場合は従来通り警告し、この画面では動作を継続します。

## 手数制限

Position.moveCountは盤面が変化した移動だけで増えます。無効移動では手数・スコア・新規タイル・乱数を消費しません。最後の許可された移動は合体・得点・新規タイルをすべて確定し、その結果のmoveCountが上限以上なら終了します。上限を超える次の移動は拒否します。

UndoはPositionの手数を戻すので、履歴と残りUndo回数があれば上限から再開できます。Undo使用数と過去の達成通知は戻しません。保存からの復元でも同じ条件を適用し、上限を超えた不正な手数は受け入れません。

## 達成と終了

目標達成と終了理由は独立しています。終了理由は時間切れ、手数上限、手詰まりの順で優先します（時間と手数は排他的なモードです）。

目標達成と終了が重なった場合は達成通知を先に表示し、「結果を見る」またはEscで終了結果へ進みます。達成通知が開いている間に時間切れになった場合も同じです。時間制限内なら「続ける」で再開できます。

- 時間切れ：Undoも移動も不可。
- 手数上限・手詰まり：閉じるだけでは再開しない。履歴・Undo回数がある場合にUndoで復帰。
- 目標達成：過去最大数字と通知済みを維持し、Undo・再読み込み・再達成でお祝いを繰り返さない。

終了通知は更新番号と理由を組にして管理します。手詰まり表示後に時間切れになったときも、時間切れとして正しく扱い、Undoが表示されなくなった場合はポップアップ内のフォーカスを保ちます。

## 保存とベスト

進行形式はversion=2に更新し、clockとoverNotifiedReasonを追加します。保存キーは従来の`my-2048-game:progress:v1`を維持して旧データを検出します。旧STEP 4の通常モードは安全に読み込み、履歴・乱数・Undo使用数・記録を維持して移行します。未知の形式は推測しません。

復元時は終了フラグを信用せず、締切・現在時刻・手数・盤面から理由を再判定します。期限切れなら終了に遷移して保存します。ベストはモードと制限値ごとに分離し、既存通常モードの比較キーは変えません。

実機・Safari／Firefoxの確認と端末時計の信頼性は、ローカルChromiumでの検証とは別です。複数タブ間の進行マージやサーバー時刻との同期は行いません。
