# STEP 4 実装・検証結果

確認日：2026-11-10（JST）。対象：`~/projects/my-2048-game`のみ。

## 実装

- Undoを既定10回、0〜10回と無制限で設定可能にしました。有効移動の直前Positionだけを記録し、盤面・スコア・手数・乱数・次のタイルIDを復元します。
- Undo使用数、過去最大数字、目標通知済みは戻しません。更新番号も単調に進めます。同じ操作のやり直しで新規タイルの位置・数字・IDが一致します。
- 手詰まりポップアップ内の「Undoで続ける」、または閉じた後のUndoで復帰できます。履歴や回数がない場合はボタンを無効にします。
- 時間切れはUndo不可、将来の手数上限は可能ならUndoで復帰できる終了理由のガードを用意しました。時間・手数制限モードと時計自体は今回実装していません。将来の経過時間・締切はPositionの外に置き、Undoで戻さない構造です。
- 同じサイズ・目標・初期枚数・出現確率・Undo設定・モードごとのベストを保存します。シードを条件に含めず、有効移動ごとに更新し、Undo・新しいゲームで下げません。
- バージョン付きの進行データとベスト記録を別キーでlocalStorageへ保存します。bigintは10進文字列です。保存拒否でもゲーム・Undo・画面内ベストを維持します。
- 再読み込み時に進行、履歴、Undo使用数、適用済み設定、達成・通知状態、乱数を復元します。編集中の値は保存しません。
- 不正JSON、型・範囲・バージョン、ID重複、不正な指数、スコアや手数・出現枚数・履歴の不整合を拒否します。終了フラグをそのまま信用せず盤面から再判定します。不正な進行では新規開始し、有効なベスト記録は維持します。
- 容量不足や保存処理予算超過では現在の盤面だけを優先保存します。無制限の履歴はメモリから自動削除せず、保存されなかったことと再読み込み後に利用できないことを表示します。

詳細な保存形式・検証式・上限は[保存・Undo仕様](persistence.md)に記載しています。

全24組合せで、ブラウザ内の保存されたPositionを純粋なエンジンの期待結果と照合しました。ページ横幅は各画面幅以内、盤面幅は420／324／254px、操作ボタンと設定入力は48px以上でした。

各画面で以下も確認しました。

- 初期上限10、0回と1回での操作禁止、無制限表示、使用数維持
- 復元時に新しいシードを要求しないこと、Undo後の同じ新規タイル、ベストが下がらないこと
- Undo設定ごとのベスト分離、編集途中の設定を復元しないこと、新規ゲームで履歴・使用数を初期化すること
- 正規の保存形式で128達成状態を読み込み、Undoして64へ戻し、再読み込みと再操作後も達成表示を繰り返さないこと
- 正規の手詰まり状態からポップアップ内Undoで復帰し、フォーカスが盤面へ戻ること
- 壊れた進行データから新規開始しても有効なベスト記録を維持すること

320pxではStorage APIの容量超過・保存拒否を検証用に再現し、警告表示、ゲーム継続、容量不足時の現在盤面優先、再読み込み後の履歴不足の明示を確認しました。製品コードにテスト専用APIや盤面操作のバックドアは追加していません。達成・終了の検証データも実際のエンジンで作った正規のセッションを保存形式で投入しています。

## 残課題・現在の制限

- iOS・Android実機、Safari・Firefoxでの確認は未実施です。
- localStorageの容量・許可は環境依存です。無制限Undoでも保存は無限ではなく、容量／処理量上限時は明示したとおり履歴が再読み込み後に使えません。この画面の履歴は維持します。
- 端末間同期や複数タブの進行マージは対象外で、同じオリジンの保存は最後の書き込みが使われます。
- 時間・手数制限、本格的なタイルアニメーション、公開は次のSTEPです。
