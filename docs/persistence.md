# Undo・記録・保存仕様

## セッション

ゲームエンジンのGameStateを変更せず、`PlaySession`が履歴と通知を管理します。Undoが復元するのはPosition（盤面、bigintスコア、手数、RngState、nextTileId）だけです。使用数、maxPowerEver、目標通知済み、終了通知の更新番号を巻き戻しません。更新番号は前進・Undoとも1増やします。

有効な移動のみを記録します。有限設定は残り回数分の直近履歴、無制限は全履歴をメモリに保持します。無制限は回数の制限がない意味で、ストレージが無限に使える意味ではありません。新しいゲームは履歴と使用数をリセットします。

目標ポップアップ中はUndoせず、「続ける」で閉じてから戻します。手詰まりは結果ポップアップ内からもUndoできます。終了を閉じただけでは移動可能になりません。Undoで復帰後に再び手詰まりになった場合は、新しい更新番号の終了通知を表示します。

終了理由`time-expired`ではUndoを拒否し、`move-limit`では履歴と回数があれば許可します。時刻情報をPositionへ含めず、Undo対象外とします。Undoを実行する直前にも現在時刻を確認するため、表示更新の合間に時間切れになってもUndoできません。

## 進行の保存形式

キー：`my-2048-game:progress:v1`。トップレベルの`version`は4。既存データを見失わないよう保存スロットのキー名はv1のまま維持します。ゲームエンジンの`rulesVersion`は従来通り`2048-v1`です。

- game：適用設定、初期シード、Position、過去最大指数、更新番号
- history：Positionの配列
- undoUsed：使用したUndo回数
- goalNotified：目標達成の通知済み状態
- overNotifiedRevision：直近の終了通知の更新番号
- overNotifiedReason：直近の終了通知の理由。同じ更新番号でも手詰まりから時間切れへの変化を識別
- clock：開始時刻・締切時刻・最後に観測した時刻。未開始／時間制限以外はすべてnull
- popup：達成／終了／なし
- status：保存時の参考状態（復元時は信用せず再計算）
- historyOmitted：容量・処理量により履歴を保存できなかった印

スコアは、符号・先頭ゼロ・指数表記を使わない10進文字列です。通常のJSON.stringifyでbigintを直接出力しません。編集中の設定は保存しません。

保存タイミングは新しいゲームの採用、有効な移動、Undo、ポップアップの開閉です。各操作内で同期保存し、ページを離れる前の遅延タイマーには依存しません。無効移動では履歴追加も手数加算も行いません。開始前の無効移動は保存もしません。時間制限中は入力が無効でも時刻を観測し、期限切れへの遷移は保存します。表示更新ごとの常時書込はせず、非表示化・pagehide・コンポーネント終了時にも時刻を保存します。

## 復元時の検証

型・項目名・バージョン、設定の範囲、正方形の要素数、タイルIDの一意性、指数・乱数・手数・更新番号を検証します。履歴も同じ検証を行い、前後のPositionが実際の4方向のいずれかの有効移動で一致することを確認します。

スコアの検証には次の不変条件を用います。Mは初期枚数＋現在の手数、Tは盤面の数字合計、Cは初期配置を含む4の出現数です。

```
C = (T − 2M) / 2
P = Σ(value × (power − 1))
score = P − 4C
nextTileId = 2M − 盤面のタイル枚数 + 1
revision = moveCount + 2 × undoUsed
```

同じ数字の合体はPを合体後の値だけ増やし、2の出現はPを増やさず、4の出現は得点せずPを4増やすため、スコア式が成立します。履歴が保存されていなくても、この検証で不整合なスコアを拒否します。出現確率が0%／100%なら盤面合計の範囲もその条件に合わせます。

保存された終了フラグやポップアップだけを信じず、盤面の手詰まり、適用済みの手数上限、保存した締切と現在時刻を再判定します。達成はmaxPowerEverと設定から再判定します。不正JSON・未知バージョン・型や算術の不整合は進行データを採用せず、新しいゲームを開始します。別キーの有効なベスト記録は保持します。この検証は型・算術・直近履歴の整合性の検証であり、暗号署名による改ざん防止ではありません。

## ベスト記録

キー：`my-2048-game:bests:v1`。形式は`{version:1, records:{条件キー:10進スコア文字列}}`です。

条件キーは版、サイズ、目標、初期枚数、4の出現率、Undo上限、モードを固定順で含み、シードを含めません。通常は従来の`["normal"]`を維持し、時間制限は`["timed", 秒数]`、手数制限は`["moves", 上限]`を含めます。既存の通常モードの比較キーとベスト保存ファイルのversion=1は変更しません。

有効な移動ごとに、それまでより高いスコアのみを更新します。Undo・新しいゲームでは下げません。復元された有効スコアが記録を上回る場合も回復します。各記録の設定とスコアを検証し、同一ファイルに壊れた項目があっても他の有効項目は残します。

書込失敗時はメモリ上のベストを維持して警告し、次の有効移動で未保存の記録を再試行します。

## 保存容量・処理量と失敗時

JSON文字列の上限は1,500,000文字、書込・復元する履歴のセル数合計（N²×履歴数）の上限は40,000です。後者は大きな無制限履歴の同期処理が画面操作を長時間止めることを避けるための処理量予算です。ブラウザ自体の保存上限は環境により異なり、これより先に失敗する場合もあります。

履歴付き保存が容量不足、または上記予算超過の場合、同じキーへ現在の盤面だけを保存します。成功しても`historyOmitted:true`とし、UIで「この画面の履歴は維持されるが、再読み込み後は使えない」と明示します。メモリ上の履歴を勝手に切り捨てません。再読み込み後は履歴が使えない旨を再表示し、現在の盤面・Undo使用数・適用設定・達成状態を復元します。

現在の盤面も保存できない場合は失敗を表示し、最後に成功した保存を消しません。保存拒否・容量超過・読み込み拒否でも、メモリ上のゲーム、Undo、ベストを使って続行できます。

## 対応範囲

localStorageは同じブラウザ・同じオリジン内の保存です。端末同期・複数タブ間のマージ・サーバー保存は行いません。未知バージョンは推測して復元せず、安全な新規開始とします。STEP 4のversion=1進行は通常モードとして読み込み、時計未開始・過去の終了理由を補完して、書込成功時に同じ保存キーへversion=4で移行します。履歴・Undo使用数・達成通知・ベスト記録を維持します。v1に存在しない時間制限データから締切を推測することはせず、不正データとして扱います。

## スペシャルモードの拡張

version=3は適用済みのスペシャル設定を保存し、v1/v2はOFFとして移行します。ONでは生成値を考慮した質量・得点検証を行い、ベスト条件に間隔・数字・置換方式を追加します。OFFの比較キーは従来のままです。追加の算術式・乱数順序・移行方法は[スペシャルモード仕様](special-mode.md)を参照してください。

## スペシャルタイムの拡張

v4は適用済み設定・変更権残数・処理済み周期・獲得／使用累計と、編集による算術差分を保存します。v1/v2/v3はスペシャルタイムOFFで移行します。編集の確定で古いUndo履歴を破棄し、変更権と編集履歴をUndo対象から外します。詳しくは[スペシャルタイム仕様](special-time.md)を参照してください。
